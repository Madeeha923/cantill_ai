# Approach

`main.py` dispatches the existing Company A and B implementations and the generic no-label implementation. Company inputs and taxonomy paths are loaded from YAML. The fixed output contains one row per input record with the required 11 fields: `record_id`, `include`, `exclusion_reason`, `supplier_key`, `item_key`, `spend`, `l1`, `l2`, `l3`, `l4`, and `confidence`.

Company A treats ERP receipts as canonical. Invoice Tool rows are eligible only when Approved or Paid; cancelled rows receive `CANCELLED`, and other statuses receive `NOT_APPROVED`. Eligible tool rows matched to ERP or identified as repeated exports receive `DUPLICATE`. Matching requires normalized PO, PO item, supplier, and a close net amount. If multiple ERP receipts are candidates, only a unique best description match that also passes the amount check is matched; ties are left included and shown as ambiguous in `outputs/company_a_matching_diagnostics.csv`. The method is heuristic, not ground-truth validated.

Company B passes USD amounts through unchanged. For non-USD amounts it uses a positive transaction rate, then a monthly FX rate, dividing local amount by units of currency per USD. Five records lack FX and three lack amounts; their internal flags and IDs/reasons are saved in `outputs/company_b_missing_spend.csv`. The fixed output schema cannot represent missing spend for included rows, so the output builder writes zero for those rows; consult the diagnostic file to distinguish them from genuine zero amounts. The input has no approval-status column; `paid_date` is not used to infer approval, and document type is not treated as approval evidence. The implemented inclusion rule checks intercompany GL descriptions and tax terms in line descriptions.

Company A held-out evaluation uses an 80/20 stratified split (`random_state=42`). TF-IDF and the linear SVM are fitted only on training records; test labels are excluded from fitting and prediction. The measured results on 29,623 training and 7,406 test records were accuracy 0.9095, macro precision 0.8803, macro recall 0.8715, macro F1 0.8700, and weighted F1 0.9100. All 40 taxonomy categories appeared in training and 38 in test; two had no held-out examples, eight had fewer than 10 test records, and six had fewer than 10 training records. No incomplete labels were excluded. The evaluation ran in 43.6 seconds on the local Windows/Python 3.13 environment; full A/B production runtime was not separately measured here.

For a generic unlabeled company, the YAML maps input columns and taxonomy levels. The fallback fits a word TF-IDF representation on full taxonomy paths, transforms line descriptions, and selects the highest cosine-similarity path. It supports three or four levels, emits exact taxonomy labels, and leaves levels below a shorter path blank. Similarity confidence is not a calibrated probability; blank or generic descriptions can still receive the first best path with a score near zero. Company C's actual schema and accuracy remain unverified until its blind files arrive. No paid LLM API is used; API cost is $0 per 1,000 lines.

Company B seed-label comparison covers 3,000 labelled rows: there were no missing predictions and inclusion agreement was 100% (confusion matrix: 450 excluded and 2,550 included correctly classified). This measures inclusion agreement only, not category accuracy.
